# Design

## Context

桌面宿主在 `show` 时创建或复用面板，在 `hide` 后按设置安排空闲释放。应用作用域保存业务状态和置顶状态。窗口级焦点由 NSGo v0.2.0 的 `desktop.PanelOptions.HideOnBlur` 处理，失焦隐藏后框架更新 `Window.Visible()`。Windows 和 Linux 的 `Lifecycle()` 在应用的任一窗口有焦点时仍可报告活跃，因此无法单独识别主窗口切到设置窗口的情况。见 [窗口事件实现](https://github.com/nsgo-dev/nsgo/blob/v0.2.0/core/window.go#L822-L831)。

## Goals / Non-Goals

**Goals:** 用窗口级焦点事件处理自动收起，让手动与自动收起共享同一套空闲释放计时。

**Non-Goals:** 功能限于内容面板。设置与关于窗口继续使用各自的关闭行为。

## Decisions

- 在 `preferences` 增加布尔偏好，读取设置前初始化为开启，这样缺少字段的旧文件也能启用功能，显式保存的 `false` 仍可读取。设置开关复用普通偏好的保存路径，保存成功后更新行为。服务设置保存时沿用当前失焦偏好，避免覆盖设置窗口较早的快照。
- 创建面板时，根据已保存的开关与置顶状态计算 `HideOnBlur`。该参数只在创建时传入。仅在计算结果改变时更换面板实例，保留应用作用域的草稿、结果和流式问答。用户在面板内切换置顶时，恢复原面板的可见状态及 Windows 窗口位置，沿用当前页面。设置窗口内修改策略时保留设置窗口焦点，已收起的面板在下次唤回时采用新策略。从关闭改为开启时，若未置顶的面板仍在设置窗口后方，则按收起处理。仅靠应用级活跃状态会漏掉同一进程内的窗口切换。
- 观察当前面板从可见到隐藏的变化，统一安排空闲释放。手动收起仍通过原入口。唤回取消正在等待的释放，热键或托盘可复用仍有效的面板。此前置顶设计以同一面板实例切换层级，策略变化时允许重建该实例，用户看到的置顶及唤回行为沿用原契约。

## Risks / Trade-offs

- 原生语言选项、应用内设置窗口与其他应用的焦点路径不同。Windows 实测分别验证这三条路径，并检查重建时没有焦点回跳、页面清空或位置跳动。
- Linux 由 GTK 报告窗口活跃状态。X11 和 Wayland 验收分别记录所用会话和可用的唤回入口，测试安排延续 Windows 优先。
